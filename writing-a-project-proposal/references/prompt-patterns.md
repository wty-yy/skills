# 项目申报写作 Prompt 模式

## 模式一，文本格式仿写

适用请求：

```text
帮我将如下文本1，转为文本2的格式，要求字数基本一致，语法一致，只需输出最后转化得到的结果
文本1
...
文本2
...
```

处理要求：

- 以文本2为格式、语法、节奏和句式基准。
- 以文本1为事实、对象、技术内容和术语来源。
- 保留文本1的核心含义，不新增未经提供的指标、单位、项目名称或结论。
- 字数与文本2基本一致，段落数和标点风格尽量一致。
- 只输出转换后的结果，不添加说明。

输出范式：

```text
根据文本2的句式，将文本1改写为同等长度、同等语法密度的项目申报文本。
```

## 模式二，DOCX模板转换

适用请求：

```text
帮我将“空间思维链的多技能具身搜索.docx”转为“格式模版.docx”的格式，要求字数基本一致，语法一致，只需输出最后转化得到的结果；最后告诉我可能需要我进一步修改的地方
```

处理要求：

- 读取源文档与模板文档，识别标题层级、段落顺序、编号方式、表述风格和字数密度。
- 将源文档内容迁移到模板结构中，保留源文档的技术事实和项目逻辑。
- 若模板存在固定字段，尽量用源文档对应内容填充。
- 若无法从源文档判断字段内容，使用稳妥的概括性表述，不虚构数据。
- 最终正文之后，列出“可能需要进一步修改的地方”。

修改建议常见项：

- 项目名称、承担单位、负责人、日期等模板字段是否准确。
- 量化指标、预算、时间节点、考核方式是否需要补充。
- 专有名词、技术路线名称、平台或系统名称是否需与正式申报书统一。
- 涉及外部数据、应用场景、合作单位的表述是否需核验。

输出结构：

```text
转换后的正文

可能需要进一步修改的地方
1. ...
2. ...
```

## 模式三，按指定文本格式转换报告

适用请求：

```text
帮我将“任务三科技报告.docx”转为文本1的格式，要求字数基本一致，语法一致，只需输出最后转化得到的结果；最后告诉我可能需要我进一步修改的地方
文本1
...
```

处理要求：

- 以用户粘贴的文本1为目标格式。
- 从 `.docx` 中提取可迁移内容，重组为文本1的段落结构和表达方式。
- 保持文本1的标题句式、编号习惯、段落长度和语法骨架。
- 保留科技报告中的关键任务、方法、指标、结论和应用场景。
- 输出最终转换结果后，简短提示需要人工确认的内容。

## 模式四，研究内容生成

适用请求：

```text
围绕下面内容，写一个以某题目为题的研究内容，字数要求500字。用三段话来写，内容不要显式地分点，避免第一、第二、第三或者首先，然后，最后的表述。写作风格要符合国家自然科学基金项目的要求，严谨、科学、避免自造词汇，同一个名词不要多种不同的表述，可信推理的表述不要改变，不要出现可解释推理的表述。避免在技术路线中出现类脑、深度学习等词。主语统一使用本研究，段落中的符号只能逗号、句号、顿号，其余符号全部不要。表述要求学术化。避免出现过多次数的本研究，保证语句通顺流畅。
```

处理要求：

- 围绕题目写成连续三段，不使用小标题。
- 每段承担一个稳定功能，通常为问题背景与目标、方法路径与机制、验证方式与预期作用。
- 不显式分点，不使用序列词。
- 严格执行禁用词、固定术语、主语和标点要求。
- 国家自然科学基金风格侧重科学问题、理论机制、方法体系和验证逻辑。
- 国家发改委项目风格侧重应用需求、关键技术、工程实现、示范验证和指标支撑。

常用约束句可复用：

```text
字数约500字。用三段话来写，内容不要显式地分点，避免第一、第二、第三或者首先，然后，最后的表述。写作风格符合国家自然科学基金项目或国家发改委项目要求，严谨、科学、避免自造词汇。同一个名词不要多种不同表述。主语统一使用本研究。段落中的符号只能使用逗号、句号、顿号。表述要求学术化，语句通顺流畅。
```

## 模式五，研究大纲生成

适用请求：

```text
围绕下面内容，写一个以某题目为题的研究内容，聚焦于某方向，避免写某方向，分段给出环境、任务分解、约束规划的研究内容。先给出三种研究大纲。
```

处理要求：

- 先生成三种大纲方案，方案之间应体现侧重点差异。
- 每种大纲保持同类粒度，通常为三级结构，一级为研究方向，二级为研究要点。
- 严格避开用户要求避免的内容边界，例如要求聚焦任务规划时，不展开运动规划。
- 标题应使用申报书常见名词短语，避免口语化和过度创新词。

输出范式：

```text
方案一
1. ...
（1）...
（2）...

方案二
...
```

## 模式六，围绕子题目扩写研究内容

适用请求：

```text
围绕下面内容，写一个以
多维约束下的协同任务分配与调度规划
（1）多维异构约束模型构建
（2）人机协同冲突消解机制
（3）基于时序规划求解算法
研究内容，无需使用小标题直接分段写，字数约800字。用三段话来写...
```

处理要求：

- 三段分别覆盖三个给定研究点，但正文中不出现小标题。
- 第一个研究点通常写模型与边界，第二个写机制与策略，第三个写算法与验证。
- 字数约800字时，每段保持均衡，不让某一段过短。
- 术语统一，例如“多维异构约束模型”“人机协同冲突消解机制”“时序规划求解算法”前后一致。

## 模式七，关键技术问题撰写

适用请求：

```text
围绕下面内容，写一个以面向真实场景的人机协同任务规划与自纠错闭环的关键技术问题，字数约500字。用三段话来写...
```

处理要求：

- 写成关键技术问题，不写成研究内容或实施方案。
- 强调“如何解决”的问题表达，可使用“如何构建”“如何实现”“如何抑制”“如何保障”等句式。
- 每段聚焦一个关键问题，保持问题导向。
- 若用户提供任务规划与自纠错材料，应覆盖环境建模、任务分解、约束规划、自纠错闭环等核心内容。

## 模式八，仿照样例精简关键技术问题

适用请求：

```text
仿照内容2精简内容1的内容：
内容1：
...
内容2：
...
```

处理要求：

- 以内容2为压缩后的目标风格。
- 每个关键技术问题通常保留“标题。在某条件下，如何……”的结构。
- 将“本研究拟……”等方案式表述改为“如何……”的问题式表述。
- 保留核心挑战、关键对象、目标结果，删除实施细节中的冗余动作。
- 每条长度与内容2接近，三条之间句式一致。

示例范式：

```text
关键技术问题一：非结构化环境语义认知与层级任务分解。在环境动态多变与任务逻辑复杂的挑战下，如何构建连续物理特征到离散逻辑状态的映射机制，利用层次化任务网络解析时序约束，建立连接抽象意图与底层动作原语的逻辑桥梁，确保任务序列的逻辑完备性与物理可执行性。
关键技术问题二：多维约束下的异构资源协同调度。在多主体协作面临资源竞争的条件下，如何构建融合物理极限与人因工效的异构约束模型，并通过冲突消解机制与时序规划算法，生成包含精确时间戳的动作序列，实现异构资源在复杂时变场景下的最优配置。
关键技术问题三：跨越数字物理鸿沟的全生命周期自纠错。在数字规划与物理执行存在本质偏差的条件下，如何构建覆盖全生命周期的自纠错机制，通过数字孪生验证与多源感知补偿，有效抑制误差跨阶段传播与累积，实现感认知、强推理与稳执行的技术闭环。
```

## 申报书语气清单

推荐表达：

- 针对，面向，围绕，聚焦，构建，形成，揭示，建立，提出，验证，支撑
- 科学问题，关键技术，技术路线，方法体系，约束模型，任务序列，闭环机制，示范验证
- 鲁棒性，可靠性，一致性，物理可执行性，任务成功率，误差抑制，协同调度

谨慎使用：

- 颠覆性，革命性，全球领先，极致，赋能，打造，全新范式
- 未经用户提供的指标、单位、年份、场景数量、预算和成果形式

常见禁用处理：

- 用户要求避免“可解释推理”时，不使用该词，也不改写为近义词干扰固定概念。
- 用户要求避免“类脑、深度学习”时，技术路线不出现这些词。
- 用户要求标点仅限逗号、句号、顿号时，避免冒号、分号、括号、引号、破折号、斜杠。
