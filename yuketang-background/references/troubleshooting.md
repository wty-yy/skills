# 视频与后台任务排查

| 现象 | 已确认原因 | 处理 |
| --- | --- | --- |
| `status` 显示 failed | 显示上次 worker 的失败记录，未必是 status 命令异常 | 同时检查命令退出码、error、日志和最后运行时间 |
| 心跳 HTTP 200，返回 `{}` | 该接口使用空确认 | 仅心跳接口允许空对象，复查 completed 后才记完成 |
| 班级接口 400001 | 旧学校课程没有关联用户信息 | 复查主账号仍为同一用户，记录 courses_unavailable 后继续；复查失败则停止 |
| 章节接口 HTTP 400 / 80019 | 可能是真正无权限，也可能学校上下文错误 | 先核对学校 ID；尤其保留合法值 0，不能用 `value or default` 替换 |
| 合法上下文仍返回 80019 | 没有该课程学习权限 | 记录不可访问并继续其他课程，不购买、不绕过权限 |
| 视频 duration=0 | 详情元数据缺失，视频本身仍可能可播放 | 查看播放器实际总时长，保存有来源的本地核对记录，再复查服务器进度 |
| 页面未完成数大于脚本 pending | 页面包含非视频内容 | 按类型核对目录，参见 course-tasks.md |
| 移动 skill 后缺入口或环境 | 启动器依赖外部目录 | 仓库版本使用本 skill 内 .venv、scripts/ykt.sh 和根目录 ykt.sh |

## 时长为 0 的恢复

先看进度接口 `video_length`，再看详情 `content_info.media.duration`。两者均缺失时，打开该节点的播放器，等元数据加载完成，读取实际总时长。不要把当前播放位置当作总时长，也不能随意填长时长或截短时长来标记完成。

已验证的缺失时长示例为 `00:08:11`（491 秒）和 `00:14:53`（893 秒）。这些数值只用于说明换算，不能套用到其他视频。

脚本支持 `.runtime/video-durations.json` 作为最后一级后备来源。键必须同时含班级 ID 与视频节点 ID；每条需 `seconds` 和非空 `source`。示例：

```json
{
  "123:456": {
    "seconds": 491,
    "source": "播放器显示 00:08:11；已核对该班级与节点"
  }
}
```

实际操作时替换示例 ID，来源记录放在被 Git 忽略的 `.runtime` 中。不要将针对用户课程的时长记录写入公共 config.json。文件缺失或没有匹配键时仍保留 pending；格式错误会停止任务，避免使用错误数据。服务器有效时长优先于后备记录；超过 max_video_seconds 的视频仍不提交。

恢复后执行 `./ykt.sh start --classroom-id <班级ID>`。服务器确认 completed 后，再刷新网页核对“已完成”。重新扫描可更新旧状态文件；无需依赖本地记录强制完成。

## 完整验证

局部修复后至少完成一次完整范围扫描，不能只凭首个视频成功或进程已启动宣布修复。此前在 55 门课程的最后一门才暴露学校 ID 为 0 的问题。

批量视频上报是模拟事件，不是播放器倍速。事件中的 sp=1 不意味着实际 1 倍速播放；需向用户准确说明行为。使用新账号、平台或课程时重新核对返回结构和完成条件。
