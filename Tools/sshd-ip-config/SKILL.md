# SSH IP Config

部署独立的 `sshd-trusted.service`，使用单独配置、端口和 PID 文件，通过 nftables 在认证前限制来源 IP。具体安装、维护和移除命令见 [readme.md](readme.md)。

## 部署前

- 复用用户已指定的目标机器、允许来源和新端口，仅补充缺失参数。检查实际 OpenSSH 版本、systemd 服务、端口占用、现有防火墙及有效认证设置。
- 通过活动 TCP 连接、登录用户及进程父子关系确认客户端来源。`SSH_CONNECTION` 在 tmux、持久终端或常驻工具中可能是旧值，不能单独据此判断当前端口。
- 保留原 SSH 配置、服务、监听端口和会话。先记录其有效配置、主进程及防火墙结构，用于变更后比较。
- 本模板适用于来源 IPv4 白名单、新入口仅监听 IPv4 的部署。IPv6 或其他防火墙管理器需要按实际环境调整，不能直接套用。
- 需要 root 权限部署和管理服务；登录客户端无需 sudo。用户提供的密码仅用于授权操作，不写入 skill、配置、命令示例或记录。

## 配置与启动

- 使用 [assets/sshd_config_trusted.in](assets/sshd_config_trusted.in)、[assets/sshd-trusted.nft.in](assets/sshd-trusted.nft.in) 和 [assets/sshd-trusted.service](assets/sshd-trusted.service) 生成部署副本。替换 IP 和端口占位符后再检查。
- 模板认证和会话参数来自已有部署，迁移时与目标机 `sshd -T` 比较，仅保留用户要求的差异；不顺带开放 root 密码登录、调整转发或更改认证方式。
- `AllowUsers *@<CLIENT_IPV4>` 允许该来源使用所有正常服务器账户，仍需账户认证。它在认证阶段检查，不能阻止其他来源占用未认证连接名额，必须配合新端口的防火墙白名单。
- `ListenAddress` 是服务器本地监听地址，不是客户端 IP。白名单填写服务器实际看到的来源地址；经过 NAT、VPN 或跳板机时可能是出口地址。
- 只维护独立 nftables 表 `inet sshd_trusted`，先允许指定 IPv4 到新端口，再丢弃其余来源。避免清空全局规则、启用原本未启用的防火墙或改动原端口和 Docker 规则。
- 使用 `nft -c -f`、`sshd -t -f` 和 `systemd-analyze verify` 检查后安装。检查目标文件是否已存在；已有部署先比较并保存备份，不覆盖无关服务。
- 服务启动前校验配置并原子加载专用规则，失败时不启动监听。通过开机启用服务恢复规则；重载时刷新自己的表，防止规则重复。
- 新实例使用独立 PID 文件。创建 OpenSSH 所需的 `/run/sshd`，停止新服务时不删除此共享目录。

## 验证与维护

- 确认新服务 active、enabled、端口监听正确，防火墙只允许指定来源；重载后规则数量不增加。
- 测试非白名单来源确实被阻止。能从真实白名单客户端测试时，确认实际认证成功及新端口的连接；结合会话进程到独立监听进程的父子关系确认所属服务。
- 无法使用真实客户端时，可在临时隔离网络命名空间中测试同一 SSH 配置和 nft 规则，分别验证允许来源、其他 IPv4 和 IPv6。模拟来源地址仅添加到隔离命名空间，不配置到宿主机，不改变真实客户端的路由；结束后清理临时进程和 PID 文件。
- 区分语法检查、隔离模拟、真实登录和重启测试，不将 active 或收到 banner 当作完整登录成功。
- 确认原 SSH 服务和会话正常、原配置及其他防火墙结构保持不变；比较防火墙时忽略随流量变化的计数器。
- 更新来源 IP 时同时修改 `AllowUsers` 与 nft 允许规则，检查后重载新服务。原服务的认证策略变化不会自动同步到独立配置。
- 停用时先停止并取消新服务的开机启动，再按用户要求移除专用规则和文件。停止服务后保留规则，不能先撤掉限制却留下开放监听。

## 限制说明与记录

`MaxStartups` 按监听进程计算未认证连接额度，同一进程仅增加端口不会隔离额度。OpenSSH 9.6 的 `MaxStartups` 是全局参数，不能用 `Match Address` 为指定 IP 豁免；其他版本以目标机手册和配置检查为准。

`MaxAuthTries` 和 `LoginGraceTime` 分别是单条连接的认证尝试数与认证期限，不是按 IP 累计失败后临时封禁。独立实例仍共享服务器资源。

只在用户要求历史或复现本次服务器时阅读 [references/deployment-2026-11-09.md](references/deployment-2026-11-09.md)。其中 IP、端口和进程号是该次部署事实，不作为其他机器的默认值。部署记录保存实际路径、参数、已执行步骤及验证范围，不保存密码和私钥。
