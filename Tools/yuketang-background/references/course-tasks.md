# 讨论、图文、作业与考试

## 范围和完成统计

先读取课程目录与“未完成”列表，按类型分开统计：`0` 视频、`3` 图文、`4` 讨论、`6` 章节作业、`5` 考试。后台视频脚本的 pending 只统计视频，不能代表整门课程的未完成数。类型 5 在不同接口或课程中可能另有用途，以页面标题与详情为准。

已验证的典型情况：目录共 74 项，视频 58 项。视频完成 55 项时，页面仍有 19 项未完成：3 个视频、5 个讨论、3 个图文、7 个章节测试和 1 个期末考试。结课确认必须回到目录核对各类任务，不能只看视频计数。

用户范围持续有效；“仅测试”“除期末外”等限制应落实到明确的任务列表。范围收窄时，停止已启动的其他任务和播放器。当前脚本没有作业、讨论或考试自动执行命令；以下是需要 agent 按具体内容执行的操作流程。

## 章节测试

1. 读取题目、选项、已有作答和 `max_retry`。章节测试可能计入成绩且仅允许一次提交；遇到不确定题目，先核对课程讲稿和资料，不能先猜再依赖揭示答案纠正。
2. 按题意作答。题目和选项可能随机排序，禁止按历史题号、旧字母顺序或上一次试卷的列表盲填。
3. 使用页面时，逐批操作后核对“答案保存成功”和已答数量。使用接口时，仅处理用户授权的班级、节点和题目 ID；提交前再次匹配当前题目 ID 与选项键。
4. 提交后读取每题 `my_count`、`my_score`、`is_right`，并回到目录确认测试“已完成”。成绩如实报告，不能把完成误写成满分。

已验证接口：

- 先读 `/mooc-api/v1/lms/learn/leaf_info/{classroom_id}/{leaf_id}/`，获得 `content_info.leaf_type_id`。
- `GET /mooc-api/v1/lms/exercise/get_exercise_list/{leaf_type_id}/?term=latest&uv_id={university_id}` 返回题目；请求需相应 `Classroom-Id`。
- `POST /mooc-api/v1/lms/exercise/problem_apply/?term=latest&uv_id={university_id}` 提交选择题，JSON 包含 `classroom_id`、`problem_id`、`answer`。单选和判断的 answer 也是数组，多选包含所有选择的键。填空及其他题型须重新检查接口格式。
- `user.my_answer` 是已交答案，`user.answer` 可能是平台揭示的标准答案；二者不能混用。已有 `my_count > 0` 的题目先检查结果，避免重复提交。

### 字体与限流

题干 HTML 中的 `xuetangx-com-encrypted-font` 可能使用字符映射字体，原始文本或无障碍树显示的字不一定是实际字形。优先查看渲染后的页面截图。批量提取时需要依据本次返回的 `font` 文件核对字形映射，映射不全时回到截图，不猜测乱码。字体文件应通过不携带账号 Cookie 的独立请求获取。不要将本次临时解码程序、第三方无明确许可的映射数据或题库直接提交到 skill。

曾在约 0.6 秒一次的提交过程中遇到 HTTP 429。处理方法：停止，遵循 Retry-After 等服务端提示；无提示时等待冷却，再降低请求频率。3.5 秒一次在一次实测中成功，但不是固定的平台限额或保证。恢复前重新获取作答记录：网络报错或中断不代表服务端没有保存，禁止直接重发整套答案。再次限流时停止排查，避免无限重试。

## 图文和讨论

图文先读取正文，再按页面要求完成阅读；已验证的阅读完成接口为 `GET /mooc-api/v1/lms/learn/user_article_finish/{leaf_id}/?cid={classroom_id}&sid={sku_id}`。随后重新读取详情的 `finish`，核对页面已读状态。

讨论必须按题目与材料撰写相关内容。用户明确要求完成学习讨论时，可在对应讨论节点提交；仅查看进度或刷视频不授权对外发言。页面编辑框可能使用 Enter 发送、Shift+Enter 换行，填写前先观察提示。发送后编辑框清空并不证明成功，应确认本人发言出现且内容正确，再通过详情 `finish=true` 或刷新后的“已发言”验证。不要因提交后的短暂“讨论区（0）”重复发送。不要通过标记阅读的接口冒充讨论发言完成。

## 期末考试

考试只在用户明确纳入范围后处理，不能从“刷视频”推断考试授权。开始前读取题量、时限、截止时间和提交规则，记录是否开始即计时、退出是否继续计时。

开始按钮若同时接受协议，遵循当前工具的确认规则，在该动作前取得所需确认；展示实际条款，不只报协议名称。已遇到“参加考试即代表同意并阅读《诚信守则公约和Cookie政策》”，包含个人完成期中、期末考试的承诺。记录用户当前的确认，不把某次确认写成未来会话的默认授权。遇到新的身份、摄像头、屏幕采集或监考要求，按具体要求重新处理。

点击开始可能在新标签页打开 `examination.xuetangx.com`：原页不变时先检查标签页列表，不连续重按开始。考试系统可能再次提示倒计时；确认后才进入题目。定时考试开始后优先完成当前流程，避免切走后忘记计时。

填答后核对全部题目的保存状态、单选/判断的选中值和多选项。交卷通常还有“提交后无法修改”的确认。用户已授权完成考试时，普通交卷确认可继续；遇到新增协议或其他必须确认的动作仍按当前工具规则处理。最终成功以“提交成功”“已交卷”和结果页为准，再刷新课程目录。记录实际得分、错题数、未作答数；成绩未发布时只报告已提交。

## 验证码的可见性

无障碍树可能长期包含隐藏的腾讯验证码 iframe，其存在不代表验证码正在拦截页面。实际操作受阻时先查看截图：只有可见验证弹窗才需要用户处理。不要仅凭“拖动滑块”文本就停止流程，也不要擅自解决验证码。用户处理后重新观察页面再继续。

## 私有记录

题目、答案草稿、讨论内容、成绩、用户资料、提交响应及核对截图只放 `.runtime/`。skill 仓库保存操作方法和脱敏案例，不保存用户答卷或会话凭据。后台 `status` 是上次脚本运行的快照，后续浏览器完成的项目需要重新扫描或检查网页，不能继续用旧文件声称它们未完成。
