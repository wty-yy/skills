# Linux 微信数据格式

## 数据与权限

| 数据 | 常见相对路径 | 读取方式 |
| --- | --- | --- |
| 聊天记录 | `db_storage/message/message_<数字>.db` | 匹配密钥后只读解密 |
| 表情索引 | `db_storage/emoticon/emoticon.db` | 匹配密钥后只读解密 |
| 月度表情缓存 | `cache/<YYYY-MM>/Emoticon/<md5前两位>/<md5>` | 可读取字节，部分文件内容仍加密 |
| 持久表情缓存 | `business/emoticon/{Persist,PersistStore,Thumb,ThumbStore}` | 格式按当前版本确认 |
| 进程内存 | `/proc/<pid>/{maps,mem}` | 相同用户不一定能读；受 ptrace 策略限制 |

读取缓存文件成功与能否解密是两件事。普通 Python 文件操作不会解除进程内存访问限制。仅在用户授权范围内使用 sudo，密码不进入文件或命令行；授权已经存在时无需重复询问。

## 数据库密钥与页解密

已验证的内存密钥形式为 `x'<64位十六进制raw-key><32位十六进制salt>'`。数据库前 16 字节为盐；先匹配盐，再校验首页 HMAC，避免把任意内存字符串当作有效密钥。32 字节 raw key 已经过派生，不再次执行 256000 轮 PBKDF2。

| 项目 | 已验证参数 |
| --- | --- |
| 页大小 | 4096 字节 |
| 数据加密 | AES-256-CBC |
| 每页尾部保留 | 80 字节，含 16 字节 IV 与 64 字节 HMAC |
| 首页盐 | 前 16 字节，取代 SQLite 文件头 |
| HMAC 密钥 | `PBKDF2-HMAC-SHA512(raw_key, salt XOR 0x3a, 2, 32)` |
| 页 HMAC 输入 | 密文主体 + IV + 4 字节小端页号 |
| 首页还原 | `SQLite format 3\0` + 解密页主体 + 80 字节保留空间 |

其余页密文主体从页首开始。每页认证成功后才能使用明文。库只在内存中还原，用 `sqlite3.Connection.deserialize()` 查询；内存副本的 SQLite 文件头第 18、19 字节改为 rollback journal 模式，以免 SQLite 尝试打开不存在的内存 WAL。

运行中的微信可能把最新消息留在 `-wal`。先校验 WAL header、盐、帧 checksum 和每页 HMAC，只应用最后一次完整提交之前的帧；忽略未提交尾部。发现有效盐对应的帧 checksum 错误或页认证失败时停止，不能悄悄返回过期记录。数据库与 WAL 在复制期间持续变化时重试快照或报告失败，不关闭用户微信。

这些参数来自本机成功读取记录，升级后需要重新验证。脚本遇到参数或认证不符会报错，不将随机数据解释成聊天内容。

## 会话与表情

消息表为 `Msg_<md5(username)>`，`Name2Id.user_name` 可用于核对会话用户名。`filehelper` 的 MD5 是 `9e20f478899dc29eb19741386f9343c8`。搜索联系人显示名需要读取联系人库，本次方案不包含显示名到用户名的自动映射。

| 字段 | 含义 |
| --- | --- |
| `local_id`、`server_id` | 本地与服务器消息标识 |
| `local_type` | 本次验证中 `1` 为文本，`47` 为表情 |
| `create_time` | Unix 秒，显示时使用用户时区 |
| `message_content` | 文本或 XML；部分记录是 Zstandard 压缩 BLOB |
| `WCDB_CT_message_content` | WCDB 压缩标识，需要结合内容格式判断 |

表情 XML 的 `<emoji>` 属性常见 `md5`、`len`、`width`、`height`、`productid`。部分消息还带下载地址或 AES 参数；不要把这些未验证参数当作本地缓存通用密钥。

`kNonStoreEmoticonTable` 可能记录自定义表情的 `md5`、`caption`、`aes_key`、`cdn_url` 等。`kStoreEmoticonFilesTable` 记录商店表情的 `md5_`、`package_id_` 和包内偏移。表情库没有目标记录不代表聊天消息不存在，应以指定会话的消息为准。

## 原始文件恢复

本次成功路径是：匹配数据库密钥 → 查询指定会话 → 获取消息 MD5 与原始长度 → 在正在运行的微信内存中寻找图片头 → 读取指定长度 → 完整 MD5 一致后导出。实际恢复的是 240×240、15 帧 GIF，原始长度 343169 字节；对应加密缓存长度为 343184 字节。该差值不能单独证明具体加密算法。

内存扫描仅检查可读写映射，不生成完整进程转储。GIF 候选还核对宽高；最终使用消息完整 MD5 校验，避免导出其他图片或误匹配字节。

| 现象 | 处理 |
| --- | --- |
| `/proc/<pid>/mem` 权限不足 | 在本次授权范围内用 sudo 运行扫描或提取子命令 |
| 找不到匹配密钥 | 核对 PID、登录账号与库路径；确认微信已打开相应会话 |
| SQLite 无该消息表 | 核对会话用户名和扫描的消息分片 |
| 没有最近消息 | 检查读取了已提交 WAL；扩大已授权的消息分片范围 |
| 原图未在内存中找到 | 在微信里重新打开目标表情后重试；不能保证历史文件仍可恢复 |
| 只有无图片头的缓存 | 保留为候选，不当作可用 GIF/PNG；本方案未实现通用缓存解密 |
| MD5 不一致 | 不导出候选，继续查找或报告未恢复 |

不要记录真实密码、密钥、账号、聊天 XML、CDN 鉴权参数或用户图片到技能仓库。
